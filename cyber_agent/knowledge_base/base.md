# База знаний: Поиск уязвимостей в OWASP Juice Shop

**Версия документа:** 1.0  
**Целевая аудитория:** Агент кибербезопасности (RAG-система)  
**Теги:** `juice-shop`, `owasp`, `web-security`, `ctf`

## 1. Внедрение кода (Injection)

### 1.1. SQL-инъекция (SQLi) при аутентификации

- **Цель:** Форма входа (Login) или поле поиска.
- **Контекст:** Juice Shop использует базу данных SQLite. Поле email уязвимо к классической аутентификационной SQL-инъекции.
- **Вектор атаки:** Введите в поле Email следующую строку: `' OR 1=1--`
- **Ожидаемый результат:** Вход в систему под первым пользователем в базе данных (обычно это `admin@juice-sh.op`). Пароль при этом игнорируется из-за комментария `--`.

### 1.2. Межсайтовый скриптинг (XSS)

- **Цель:** Поле поиска (Search Bar) или форма обратной связи (Contact Us).
- **Контекст:** Приложение не экранирует ввод пользователя в некоторых полях. Много где реализована защита CSP (Content Security Policy), но некоторые векторы обходят её.
- **Вектор атаки (Поиск):** `<iframe src="javascript:alert(`xss`)">`
- **Вектор атаки (Track Order):** В поле "Order ID" на странице `/track-order` введите: `<iframe src="javascript:alert(`xss`)">`

## 2. Нарушение контроля доступа (Broken Access Control)

### 2.1. Небезопасная прямая ссылка на объект (IDOR)

- **Цель:** Страница профиля пользователя или история заказов.
- **Контекст:** API эндпоинт `/rest/user/whoami` возвращает данные текущего пользователя, но принимает параметр `id` или полагается на токен, который можно подменить, если он хранится в localStorage. Более простой вектор: манипуляция `Basket ID`.
- **Вектор атаки:**
    1. Создайте корзину (Basket) как обычный пользователь.
    2. Перехватите запрос или измените URL, подставив `bid` (Basket ID) другого пользователя (например, `bid=2` или `bid=3`).
    3. Перейдите по адресу `/basket` с измененным ID.
- **Ожидаемый результат:** Вы увидите товары в корзине другого пользователя и сможете оформить заказ от его имени.

### 2.2. Повышение привилегий через JWT

- **Цель:** Токен аутентификации (JSON Web Token).
- **Контекст:** Juice Shop использует JWT для сессий. Ключ подписи (secret) по умолчанию слабый или известен.
- **Вектор атаки:**
    1. Получите свой JWT из LocalStorage или Cookies.
    2. Декодируйте его (например, на сайте jwt.io).
    3. Измените поле `role` с `customer` на `admin` или `deluxe`.
    4. Подпишите токен заново, используя известный секретный ключ Juice Shop (часто это `your_jwt_secret` или можно подобрать брутфорсом, так как алгоритм может быть `none` или слабый HMAC).
- **Ожидаемый результат:** Получение административного доступа к разделам `/administration`.

## 3. Раскрытие конфиденциальных данных (Sensitive Data Exposure)

### 3.1. Скрытая директория FTP

- **Цель:** Директория `/ftp`.
- **Контекст:** Разработчики оставили старую, забытую директорию, которая не защищена аутентификацией и не запрещена в `robots.txt`.
- **Вектор атаки:** Перейдите по прямому URL: `http://<juice-shop-url>/ftp/`
- **Ожидаемый результат:** Вы увидите список файлов, включая `acquisitions.md` (документ о слияниях и поглощениях) и файлы купонов (например, `coupons_2013.md.bak`).

### 3.2. Утечка через исходный код (Client-Side)

- **Цель:** Файл `main.js` или `configuration.yml`.
- **Контекст:** В клиентском коде жестко зашиты пути к административным панелям или секретные вопросы безопасности.
- **Вектор атаки:** Откройте DevTools (F12), перейдите в вкладку Sources и выполните поиск по строке `"admin"` или `"password"`. Найдите ссылку на `/score-board` или `/administration`.
